# 亚马逊图片工作台北极星指标与运营成功指标

## 项目定位

当前项目的核心价值不是“调用 AI 生成图片”，而是帮助 Amazon 运营把一个商品从资料、参考图、标准六视图、图片策划推进到可用于 Listing、A+ 或 DSP 的成套图片资产。

因此运营指标应围绕“完成可用商品图套”设计，而不是围绕调用量、token 或单张图片数量设计。调用量和 token 是成本与稳定性指标，不是成功指标。

## 北极星指标

**每周完成的可上架商品图套数。**

英文口径可写作：`Weekly Amazon-ready Image Sets`。

一个商品图套计入北极星指标，需要同时满足：

1. 存在明确的商品工作区。
2. 工作区中有商品资料和至少 1 张原始参考图。
3. 工作区已确认标准 6 视图。
4. 对应工作流的目标图片位已生成成功。
5. 至少出现一个可用信号。

按工作流定义目标图片位：

| 工作流 | 完成口径 |
| --- | --- |
| Listing 图 | `MAIN + PT01-PT06` 均有成功输出 |
| A+ 大图版 | `A+L01-A+L05` 均有成功输出 |
| A+ Standard | `A+S01-A+S08` 均有成功输出 |
| A+ Premium | `A+P01-A+P06` 均有成功输出 |
| DSP | 当前 DSP 策划生成的全部素材位均有成功输出 |

可用信号包括：

- 用户下载了套图或其中图片。
- 用户收藏了图片。
- 用户将输出图复用为参考图、风格图或继续编辑源图。
- 后续新增“标记可用 / 已采纳”动作。

公式：

```text
每周完成的可上架商品图套数 =
count(distinct productWorkspaceId + workflow)
where 工作区完成标准 6 视图确认
and 目标图片位全部成功生成
and 存在至少一个可用信号
and finishedAt 落在统计周内
```

## 为什么不把生成图片数作为北极星

生成图片数只能说明消耗增加，不能说明运营拿到了可用资产。单纯优化生成图片数会鼓励重复试错、增加 token 和图片 API 成本，并可能掩盖“很多图生成了但没有被采用”的问题。

本项目可以继续展示生成图片数，但它应作为产能和成本辅助指标，不作为北极星指标。

## 运营成功指标

### 1. 激活

目标：新用户能进入完整生产路径。

| 指标 | 口径 |
| --- | --- |
| 7 日新用户工作区创建率 | 7 日内创建过商品工作区的新用户 / 新注册用户 |
| 资料准备率 | 有商品文案且有参考图的工作区 / 新建工作区 |
| 首次 AI 策划完成率 | 7 日内成功生成任一 Listing、A+ 或 DSP 策划的新用户 / 新注册用户 |
| 首套图完成率 | 7 日内完成首个可上架商品图套的新用户 / 新注册用户 |

建议首阶段目标：

- 资料准备率达到 70% 以上。
- 首次 AI 策划完成率达到 60% 以上。
- 首套图完成率达到 25% 以上。

### 2. 生产漏斗

目标：定位用户卡在哪一步。

| 阶段 | 指标 |
| --- | --- |
| 工作区创建 | 新增商品工作区数 |
| 资料准备 | 有文案、有参考图的工作区数 |
| 六视图生成 | 生成过标准 6 视图的工作区数 |
| 六视图确认 | 已确认标准 6 视图的工作区数 |
| AI 策划 | 策划成功的工作区数 |
| 风格板 | 生成并选择风格的工作区数 |
| 图片生成 | 目标图片位至少生成 1 张的工作区数 |
| 套图完成 | 达到对应工作流完成口径的工作区数 |
| 可用确认 | 有下载、收藏、复用或标记可用信号的套图数 |

核心转化率：

```text
六视图确认率 = 已确认标准 6 视图工作区 / 有参考图工作区
策划成功率 = 策划成功工作区 / 发起策划工作区
套图完成率 = 完成目标图片位工作区 / 策划成功工作区
可用采用率 = 有可用信号套图 / 完成目标图片位套图
```

### 3. 效率

目标：减少运营从商品资料到可用图片的等待和返工。

| 指标 | 口径 |
| --- | --- |
| 首张可用图耗时 P80 | 工作区创建到首张有可用信号图片的 P80 时长 |
| 套图完成耗时 P80 | 工作区创建到套图完成的 P80 时长 |
| 单图生成耗时 P80 | 任务 `createdAt` 到 `finishedAt` 的 P80 时长 |
| 六视图返工轮次 | 每个工作区的 `sixViewVersions.length` |
| 单可用图平均生成张数 | 成功输出图片数 / 有可用信号图片数 |

建议首阶段目标：

- 单图生成耗时 P80 小于 5 分钟。
- 首张可用图耗时 P80 小于 30 分钟。
- 六视图确认前的生成轮次中位数不超过 2。

### 4. 质量

目标：衡量图片是否被运营认为可继续使用。

| 指标 | 口径 |
| --- | --- |
| 图片采用率 | 有下载、收藏、复用或标记可用信号的图片 / 成功输出图片 |
| 套图采用率 | 有可用信号的套图 / 完成目标图片位套图 |
| 风格复用率 | 使用历史风格图或图库图作为当前风格的生成任务 / 总生成任务 |
| 继续编辑率 | 输出图被继续编辑的次数 / 成功输出图片数 |
| 合规返工率 | 因主图、平台标识、价格、评价、促销等合规原因重新生成的任务 / 总任务 |

当前代码已经有收藏、复用、继续编辑入口；下载动作和“标记可用 / 返工原因”需要新增事件记录。

### 5. 稳定性

目标：保证生产链路可靠。

| 指标 | 口径 |
| --- | --- |
| AI 代理成功率 | 成功 AI 代理调用 / 总 AI 代理调用 |
| 生图任务成功率 | `status = done` 且 `outputImages.length > 0` 的任务 / 总任务 |
| 失败任务率 | `status = error` 的任务 / 总任务 |
| 空输出率 | 成功响应但无图片输出的任务 / 成功响应任务 |
| P80 失败恢复时间 | 失败任务到下一次同工作区成功任务的 P80 时长 |

建议首阶段目标：

- AI 代理成功率达到 90% 以上。
- 生图任务成功率达到 85% 以上。
- 空输出率低于 3%。

### 6. 成本

目标：让完成一套可用图的成本可控。

| 指标 | 口径 |
| --- | --- |
| 每套图 token 消耗 | 完成可上架商品图套关联的 `totalTokens` |
| 每套图生成任务数 | 完成可上架商品图套关联的生图任务数 |
| 每套图失败调用数 | 完成可上架商品图套前的失败调用数 |
| 无效消耗占比 | 失败任务 token 与图片调用成本 / 总成本 |

北极星的成本护栏：

```text
每周完成的可上架商品图套数增长时，
每套图失败调用数和无效消耗占比不能同步上升。
```

### 7. 留存与复用

目标：确认用户不是只试一次，而是把它作为运营工作台持续使用。

| 指标 | 口径 |
| --- | --- |
| 7 日回访率 | 首次完成策划后 7 日内再次访问的用户 / 完成策划用户 |
| 二次工作区率 | 7 日内创建第 2 个工作区的用户 / 创建过工作区用户 |
| 历史资产复用率 | 使用历史风格、历史输出或图库参考的任务 / 总任务 |
| 多工作流扩展率 | 同一工作区完成 Listing 后继续完成 A+ 或 DSP 的比例 |

## 当前项目已有可统计数据

现有代码已经支持或接近支持以下数据：

- 用户、角色、状态、最近登录。
- `usage_events` 中的调用次数、成功失败、生成图片数、token。
- 商品工作区 `ProductWorkspace`。
- 工作区参考图、标准 6 视图版本、确认版本。
- Listing、A+、DSP 策划结果。
- 任务状态、输出图片、耗时、收藏状态。
- 任务与工作区、图片位、批次、六视图版本的关联元数据。

这些数据可以先支撑：

- 调用成功率。
- 生图成功率。
- 生成图片数。
- token 消耗。
- 工作区数。
- 标准 6 视图确认率。
- 任务完成耗时。
- 收藏率。
- 套图完成率的初版统计。

## 建议新增事件

为了让北极星指标可被准确统计，建议新增轻量事件表或事件 JSON 记录：

| 事件 | 触发时机 |
| --- | --- |
| `workspace_created` | 新建商品工作区 |
| `workspace_reference_added` | 添加原始参考图 |
| `six_view_generated` | 标准 6 视图生成完成 |
| `six_view_confirmed` | 用户确认标准 6 视图 |
| `planner_started` | 发起 AI 策划 |
| `planner_succeeded` | AI 策划成功 |
| `style_selected` | 选择当前风格 |
| `image_task_submitted` | 提交图片生成 |
| `image_task_succeeded` | 图片生成成功 |
| `image_downloaded` | 下载图片或批量下载 |
| `image_favorited` | 收藏图片 |
| `image_reused` | 输出图被作为参考图、风格图或编辑源图 |
| `image_marked_usable` | 用户手动标记可用 |
| `image_rework_reason_selected` | 用户选择返工原因 |

每条事件至少包含：

- `userId`
- `productWorkspaceId`
- `workflow`
- `amazonSlot`
- `taskId`
- `imageId`
- `createdAt`

没有对应对象时字段可为空，但不要丢失已有上下文。

## 看板建议

管理端运营看板优先展示 5 个区域：

1. 北极星：本周可上架商品图套数、环比、近 8 周趋势。
2. 漏斗：工作区创建到可用确认的阶段转化。
3. 效率：首张可用图耗时、套图完成耗时、单图生成耗时。
4. 质量：图片采用率、套图采用率、返工原因 Top 5。
5. 成本稳定性：调用成功率、失败率、token、每套图消耗。

普通用户个人统计页可以只展示：

- 本周完成套图数。
- 当前进行中的工作区。
- 已生成图片数。
- 已采用图片数。
- 本周 token 使用量。

## 当前不确定项

当前仓库没有看到 Seller Central 上传状态、Amazon Listing 转化率、广告销售额或真实业务 GMV 数据接入。因此本指标体系衡量的是“图片生产运营成功”，不是“图片上线后的销售成功”。

如果后续接入 Amazon 业务数据，最终业务成功指标可以升级为：

```text
由本工具产出的图片上线后，带来的 Listing CVR、CTR 或广告素材 ROAS 提升。
```

在没有销售归因数据之前，不建议把销售额或转化率作为当前项目北极星指标。
