# Amazon 草稿质量与高清终稿流程设计

## 背景

Amazon 图片工作台当前把 AI 策划、风格板、单张提交和批量提交串成一个生产流程。用户可以选择 `1K / 2K / 4K`，系统会把该尺寸直接用于正式生图。这样的问题是：早期试错也会按接近正式生产的成本运行，尤其在用户上传多张高分辨率参考图时，请求体积和等待时间都会变大。

本次改动的目标不是改变 Amazon 图片规格，而是把“草稿确认”和“高清终稿”拆开。草稿阶段仍使用 Listing、A+、DSP 原本要求的尺寸和比例，只降低生成质量，并在送入 AI 前压缩用户上传参考图；用户确认方向后，再制作高清终稿。

## 目标

- 风格板、初步生图和高清终稿形成清晰流程：先低成本确认方向，再高清生产。
- 草稿图尺寸保持原业务规格和比例，不使用随意的小尺寸。
- 草稿阶段通过 `quality: medium` 和参考图压缩加速。
- 高清阶段沿用当前最终尺寸选择，并使用更高质量参数。
- 用户上传参考图在送入 AI 前按阶段压缩，避免原图过大拖慢请求。
- 任务历史可以区分草稿任务和高清终稿任务，便于复用和追踪。

## 非目标

- 不新增后端图片表或独立资产中心。
- 不改变 Amazon Listing / A+ / DSP 的规格要求。
- 不自动把所有草稿批量高清化。
- 不引入新的服务商配置字段。
- 不绕过现有 `submitTask`、任务历史和隐藏风格参考机制。

## 尺寸策略

尺寸必须来自现有业务规格：

- Listing：继续使用当前 Listing 目标尺寸逻辑，按用户最终档位选择 `1024x1024 / 2048x2048 / 4096x4096`。
- A+：继续使用模块上传规格和现有生成尺寸计算，例如 `970x300`、`970x600`、`220x220`、`1464x600`、`463x625` 等比例。
- DSP：继续使用现有 DSP 素材规格，例如 `300x250`、`728x90`、`160x600`、`970x250`、`600x500`、`1242x375` 等比例。

草稿阶段不再缩小这些尺寸。草稿和高清的区别只在质量、压缩和任务语义上。

## 质量策略

引入 Planner 生成阶段：

- `draft`：草稿阶段，用于快速看方向。
- `final`：高清终稿阶段，用于确认后的正式生产。

默认参数：

- 草稿生成：`quality: medium`，`output_format: jpeg`，沿用当前输出压缩率。
- 高清生成：`quality: high`，`output_format: jpeg`，沿用当前输出压缩率。

如果后续实测 `medium` 仍慢，可以把草稿默认切到 `low`。本设计不在第一版提供 UI 切换，避免多一个操作维度。

## 参考图压缩策略

现有 `src/lib/referenceImagePayload.ts` 已有参考图压缩管线：首轮最长边 1024、质量 0.82，fallback 最长边 768、质量 0.72，并限制总 payload。该管线需要扩展为按阶段选择压缩档位。

草稿阶段：

- 用户上传参考图送 AI 前压缩得更激进。
- 建议最长边 768、质量 0.72。
- fallback 可降到最长边 640、质量 0.65。
- 目标是保留产品形状、颜色、关键结构和主要材质方向。

高清阶段：

- 继续使用当前较高质量压缩策略。
- 首轮最长边 1024、质量 0.82。
- fallback 最长边 768、质量 0.72。
- 目标是尽量保留产品边缘、材质和细节。

遮罩编辑仍需保持主图和 mask 同尺寸缩放。已有 `prepareReferenceImageAndMaskPayload` 会成对压缩第一张参考图和遮罩，新增阶段参数时也必须覆盖该路径。

## 风格板

风格板仍是隐藏风格参考，不是最终图。风格板生成走草稿阶段语义：

- 使用低质量参数。
- 不附加产品参考图，保持当前“风格候选独立生成”的行为。
- 文案从固定强调 `1024x1024` 改为“视觉风格参考板”，避免用户误解为最终规格。
- 如果代码继续保留 `1024x1024` 尺寸，也只作为风格板画布规格，不代表高清生产。

## 单张工作流

当前动作栏的“填入 / 提交”需要拆成两个明确动作：

1. “生成草稿”
   - 写入当前图片位 prompt。
   - 设置任务分类为 Amazon workflow。
   - 设置 `generationStage: draft`。
   - 使用草稿质量参数。
   - 使用草稿参考图压缩档位。
   - 成功提交后，该图片位状态为“草稿已提交”。

2. “制作高清”
   - 用户从草稿任务结果进入。
   - 使用同一 prompt、同一图片位、同一 planner session、同一隐藏风格参考。
   - 设置 `generationStage: final`。
   - 使用高清质量参数。
   - 使用高清参考图压缩档位。
   - 如果参考图数量未超过上限，把确认的草稿输出图追加为构图参考。
   - 成功提交后，该图片位状态为“高清已提交”。

“填入”可以保留为手动编辑入口，但主流程应鼓励直接生成草稿。

## 批量工作流

“提交未提交项”改为批量生成草稿：

- 对所有未提交草稿的图片位逐个提交草稿任务。
- 每个 job 保留原目标尺寸和比例。
- 每个 job 使用草稿质量和草稿参考图压缩档位。
- 批量流程仍等待每个任务完成后再提交下一个，沿用当前节奏控制。

不在第一版做“批量制作高清”。高清必须由用户逐张确认后触发，避免把未确认草稿批量转成高成本任务。

## 任务元数据

在 `TaskRecord.category` 中增加可选字段：

- `generationStage?: 'draft' | 'final'`
- `draftSourceImageId?: string`

用途：

- `generationStage` 区分草稿和高清终稿。
- `draftSourceImageId` 记录高清任务来自哪张草稿图。
- 历史列表、详情弹窗、复用配置可以显示和恢复正确语义。

旧任务没有该字段时按当前行为处理，视为未分阶段的历史任务。

## UI 行为

Amazon Planner 顶部的 `1K / 2K / 4K` 改为“最终清晰度”，说明它影响高清终稿。草稿仍按当前图片位尺寸逻辑生成，只降低质量。

动作区展示：

- 当前图片位、目标尺寸、草稿质量、最终清晰度。
- 草稿未提交：主按钮“生成草稿”。
- 草稿已提交：提示用户在任务结果确认后制作高清。
- 高清已提交：显示“高清已提交”。

任务详情或任务卡片提供“制作高清”入口：

- 仅 Amazon 草稿任务显示。
- 草稿任务必须已有输出图。
- 点击后复用任务 prompt、category、参考图和 style reference，并追加草稿输出图作为参考图。

## 数据流

草稿生成：

1. Amazon Planner 构建 prompt 和 category。
2. 设置 `category.generationStage = 'draft'`。
3. 设置草稿质量参数。
4. `submitTask` 根据 category 阶段选择参考图压缩档位。
5. 生成任务写入历史。

高清生成：

1. 用户在草稿输出上点击“制作高清”。
2. 从草稿任务恢复 prompt、category、planner session 和 style reference。
3. 设置 `category.generationStage = 'final'` 和 `draftSourceImageId`。
4. 设置高清质量参数。
5. 在参考图数量允许时追加草稿输出图。
6. `submitTask` 使用高清参考图压缩档位。
7. 高清任务写入历史。

## 错误与边界

- 草稿图不存在：提示“草稿图不存在，请重新生成草稿”。
- 追加草稿图后超过参考图上限：不追加草稿图，但继续高清生成；提示参考图数量已达上限。
- 隐藏风格板丢失：沿用现有提示，要求重新生成并选择风格板。
- 旧任务没有 `generationStage`：不显示“制作高清”入口。
- 自定义服务商不支持 `quality: medium` 或 `quality: high` 时，沿用现有参数归一化和接口错误提示。

## 测试范围

- `referenceImagePayload`：按 `draft/final` 阶段选择不同压缩请求。
- `AmazonPlanner`：草稿生成使用原目标尺寸但质量为 `medium`，不会改成任意小尺寸。
- `AmazonPlanner`：批量提交变为批量草稿，不自动高清。
- `store`：Amazon 草稿任务提交时使用草稿压缩档位。
- `store`：高清任务可从草稿任务生成，并记录 `draftSourceImageId`。
- UI 源码测试：按钮文案从“提交生成”转为“生成草稿 / 制作高清 / 高清已提交”语义。

## 迁移

不需要数据迁移。新增字段都是可选字段，旧任务继续按原历史任务展示和复用。

## 后续调整原则

草稿质量默认使用 `medium`。如果实际接口速度仍不够快，再把默认值改为 `low`。
